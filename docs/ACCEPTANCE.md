# Матрица приёмки

Это требования к будущему пилоту на целевой VM. Таблица **не является отметкой о прохождении**: живой Cloud.ru/hub/tailnet/OAuth/inference тест из факта создания репозитория не следует. Результаты фиксируются с временем, VM и конкретным локальным профилем. Публичные примеры `100.64.0.10`, `tail000000.ts.net`, `tag:ai-egress-hub` не заменяют параметры, подтверждённые владельцем.

## Разные уровни результата

| Уровень | Доказательство | Чего не доказывает |
| --- | --- | --- |
| `installed` — отметка оператора | Пакеты/служба/CLI проверены фактическими командами; отдельно указан `package_verified` | Tailnet, маршрутизацию, аккаунт или запрос Codex |
| `NETWORK_VERIFIED` — результат `verify` | Свежий IPv4-снимок прошёл все автоматические сетевые проверки | Полный инвентарь будущих DNS/endpoint-ов, IP на стороне OpenAI, реальный запрос Codex |
| `CODEX_VERIFIED` — ручная отметка | Собственный вход, успешный реальный запрос и наблюдаемое покрытие endpoint-ов | Постоянный fail-closed или работу всех будущих версий клиента |

`status` выводит сохранённый прогресс; это не свежая проверка готовности. `verify` записывает `codex_acceptance: NOT_TESTED`. После `login`/`launch` CLI оставляет `MANUAL_VERIFICATION_REQUIRED`; автоматической команды присвоения `CODEX_VERIFIED` нет.

## Обязательные проверки

Все CLI-команды ниже запускаются из корня репозитория:

```bash
sudo env PYTHONPATH="$PWD/src" python3 -m tailnet_bootstrap.cli status
sudo env PYTHONPATH="$PWD/src" python3 -m tailnet_bootstrap.cli verify
```

| Проверка | Команда / источник доказательства | Условие приёмки | При неуспехе |
| --- | --- | --- | --- |
| Платформа | `/etc/os-release`, `uname -m`, `ps -p 1 -o comm=` | Ubuntu 22.04/24.04 или Debian 12/13, amd64/arm64, systemd | Остановить установку |
| Установка | `status`, `systemctl is-active tailscaled.service`, `tailscale version`, Codex `--version`/`--help` по сохранённому пути | CLI работают, daemon active; для новой установки Codex 0.172.0 и `package_verified=true` | Не отмечать весь `installed` |
| Существующий Codex | `installation.codex` в state | Версия/help работают; отдельно указано, подтверждён ли полный пакет | `package_verified=false` не скрывать |
| Права state | `sudo stat -c '%a %U %n' /var/lib/tailscale-codex-bootstrap /var/lib/tailscale-codex-bootstrap/state.json` | `700 root` для каталога, `600 root` для файлов; секретов нет | Исправить штатную причину, не публиковать файлы |
| Профиль перед установкой | `configure`, локальный JSON и подтверждение владельца | Tailscale IPv4 hub, MagicDNS suffix, тег и публичный IPv4 согласованы; локальный IP VM отличается от `hub_ip`; профиль создан до `install`/`connect` | Не использовать пример как рабочую конфигурацию |
| Tailscale identity | `verify` → `evidence.tailnet`, Self ID | Running, suffix равен `expected_tailnet` рабочего профиля, собственный Self ID | Владелец исправляет регистрацию без автоматического reset |
| Hub | `verify` → `evidence.hub`, маршруты; роль/policy отдельно администратором | `hub_ip` и `connector_tag` профиля у одного online-узла; App Connector/approvals настроены | `NEEDS_HUB_ADMIN` |
| Подтверждение изменений | `apply` и `network.baseline` в локальном state | Аудит выполнен до изменения, подтверждение дано явно, baseline сохранён | Не включать приём маршрутов вручную |
| Область маршрутов | `route_audit`, `evidence.primary_routes`, `offered_routes` | Нет неожиданных/конкурирующих маршрутов; рассмотрены предлагаемые tailnet routes | Администратор разбирает scope |
| Текущий DNS → IPv4 | `evidence.dns`, `evidence.route_checks` | Каждый текущий A-адрес публичный, маршрут `tailscale0`, точный `/32` PrimaryRoute принадлежит hub | `NETWORK_NOT_VERIFIED` / `NEEDS_HUB_ADMIN` |
| IPv6 | `evidence.dns`, `route_checks`, `ipv6_default_routes` | Нет доступного или неизвестного пути к AAAA; IPv6 default отсутствует | Отдельное решение и приёмка IPv6; не отключать молча |
| DNS/exit/proxy | `evidence.prefs`, имена proxy-переменных | CorpDNS и RouteAll true, exit node не выбран, активного proxy нет | Разобрать существующую конфигурацию |
| Независимый echo | `control_endpoint_observed_ipv4` | `api.ipify.org` включён в connector domains и видит проверенный публичный IPv4 hub | Не считать egress подтверждённым |
| Прямой не-AI контроль | `non_ai_observed_ipv4` и его маршруты | `checkip.amazonaws.com` вне domains, идёт не через tailscale0, видит обычный выход VM, отличный от hub | Выборочность не подтверждена |
| Свежесть | `readiness`, `checked_at`, `blockers`, exit code `verify` | `NETWORK_VERIFIED`, свежее время, `[]`, exit code 0 | Сохранить точные блокеры |
| Собственный аккаунт | Шаг `login`, владелец завершил device auth | Вход в свой аккаунт без передачи файлов/секретов | Ручное участие; Codex не принят |
| Реальный запрос | `launch`, фактический полный ответ | Успешный запрос, включая завершение streaming | Codex не принят |
| Покрытие endpoint-ов | Наблюдения во время OAuth/device polling, inference и streaming; сопоставление DNS/маршрутов с профилем | Реально использованные направления покрыты; метод, время и пробелы записаны | `MANUAL_VERIFICATION_REQUIRED` |
| Откат | `rollback`, выбранное `RouteAll` после него | Восстановлен baseline только при совпадении идентичности/профиля/ожидаемого значения | Не форсировать, передать блокер владельцу |
| Переподключение | Разрыв терминала и `sudo tmux -L ai-egress-bootstrap attach -t node-bootstrap` | Тот же ещё живой процесс продолжился | Разобрать сессию/доступ |
| После reboot | Новый запуск launcher и чтение state | Этапы продолжаются по state; старого процесса/истории tmux не ожидают | Не обещать персистентность процесса |

## Ручной пилот Codex

Минимальная реальная проверка — собственный device auth и обычный запрос через нативный CLI, начатые после успешного `verify`. Для наблюдения соединений можно использовать `sudo ss -Hntp state established '( dport = :443 )'`, а для известных имён — `getent ahostsv4 FQDN` и `ip -j route get IP`. По IP без имён нельзя доказать полноту доменного инвентаря. Если в доступной среде нет надёжного способа увидеть реальные endpoint-ы, оставьте ручную приёмку незавершённой.

Не записывайте URL/коды входа, содержимое авторизации, текст пользовательских запросов или токены в общий отчёт. Достаточно времени, типа операции, перечня обнаруженных endpoint-ов, DNS/маршрутных доказательств и успешности ответа. Неполный список доменов исправляется согласованно на hub и в клиентском профиле с повторным аудитом/приёмкой.

## Границы утверждений

- Echo доказывает наблюдаемый исходный IP только у независимого echo. IP, увиденный OpenAI, этим не измерен.
- App Connector маршрутизирует IP для всех процессов. Общий CDN/IP может затронуть домены вне списка.
- `NETWORK_VERIFIED` относится к времени и DNS-снимку проверки. Новые ответы, DoH, IPv6, UDP/443 и дополнительные endpoint-ы требуют проверки.
- При исчезновении connector route возможен прямой выход. Строгий fail-closed не реализован и не принят.
- Unit-тесты с подменёнными командами проверяют логику программы, не живую инфраструктуру и не успешный Codex OAuth/inference.

Итоговый акт содержит независимые строки: `installed`, `package_verified`, сетевой результат и время, ручной результат Codex, блокеры и следующий ответственный. Не заменяйте их одним словом «готово».
