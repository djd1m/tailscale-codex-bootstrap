# Независимая проверка bootstrap

Проверены Python-модули, launcher и тесты локального рабочего дерева. На момент проверки 68 тестов прошли. Проверки с реальной VM, обмен трафиком через коннектор и вход в Codex не проводились.

## Найденные проблемы

| Приоритет | Участок | Сценарий и необходимое изменение |
|---|---|---|
| Высокий | `bin/bootstrap`, `cli.execute`, `cli.install`, `cli.connect` | Проверка собственного IP хаба находится в `apply_client`, после установки и подключения в wizard. На действующем хабе launcher может установить зависимости, а `install` включает и запускает `tailscaled`. Блокировать клиентские изменения, когда локальный узел имеет IP хаба, до apt, systemctl и Tailscale enrollment. Диагностика хаба допускается. |
| Высокий | `network.apply_client` | Одного тега и статуса online достаточно, чтобы принять маршруты при пустом наборе маршрутов коннектора. Проверка IPv6 и выборки сети выполняется позднее. Когда проверка завершается ошибкой, RouteAll остаётся включённым и принимает будущие одобренные маршруты. Сверять доступную информацию о выбранных маршрутах и IPv6 до изменения. Если часть сведений недоступна до включения, использовать обратимую пробу и возвращать изменённое значение при провале проверки. |
| Высокий | `network.rollback` | При первом apply с уже включённым RouteAll исходное значение true сохраняется. Если позднее оператор выключит RouteAll, а следующий apply включит его, rollback сравнит текущее значение с первым true, сообщит `already_restored` и оставит RouteAll включённым. Восстанавливать значение `before` той операции, которая действительно изменила настройку. |
| Высокий | `cli.codex_action`, `installers.ensure_codex` | Launcher повышает права до root и запускает интерактивный Codex и проверку найденного бинарника от root. Запись учётных данных и исполнение команд агентом оказываются в контексте root. Установка и проверка пользовательского CLI, вход и интерактивный запуск должны выполняться от отдельного непривилегированного пользователя. Привилегированные операции должны использовать предсказуемый PATH. |
| Средний | `cli.configure`, `network.apply_client` | После rollback запись `network` остаётся непустой, поэтому configure продолжает отклонять изменение профиля, а apply отклоняет новый хеш. Хранить историю отдельно от активной привязки либо снимать привязку при завершении rollback. |
| Средний | `network._probe`, `cli.codex_action` | По умолчанию curl загружает конфигурацию пользователя. Она может отключить проверку TLS или изменить параметры согласованной пробы. Передавать `--disable` первым аргументом curl, а доверенные конфигурации ОС и переменные окружения проверять отдельно. Codex наследует собственные настройки и переменные, например `OPENAI_BASE_URL`; приёмка одного профиля не доказывает маршрут при переопределённом провайдере. |
| Средний | `network.verify` | Строгая сверка текущего списка DNS-ответов со всеми маршрутами заставляет проходить проверку только при совпадении снимков. У выученных адресов возможны ротация DNS и сохранение старого объявления, а заранее разрешённый CIDR может покрывать новый ответ. Для запуска нужен осознанный выбор между пилотом с одобренными /32 и версионируемым утверждённым списком маршрутов. Широкий грант либо обход ограничения не решает вопрос области доступа. |
| Средний | `state.StateStore`, `cli.atomic_json`, `bin/bootstrap` | Настраиваемые пути и окружение используются root-процессом. Проверяется владелец конечной папки состояния, но не доверенность её предков. Профиль читается с переходом по ссылке, а launcher дополняет унаследованный PYTHONPATH и запускает корневую оболочку после завершения. Для операций root использовать доверенный каталог состояния и контролируемое окружение, проверять происхождение файла профиля и завершать привилегированный сеанс без автоматической оболочки. |
| Средний | `installers.ensure_codex` | Если прерванная установка оставила рабочий бинарник без вспомогательных файлов, следующий запуск возвращает успех с `package_verified=false`. Отличать чужую установку, которую нужно сохранить, от неполной собственной установки, которую можно безопасно завершить или явно заблокировать. Проверки наличия файлов и битов исполнения служат проверкой комплектности, а целостность загрузки отдельно обеспечивается закреплённым хешем скрипта и проверкой артефактов upstream. |

## Дополнительные проверки

- Две ошибки воспроизведены с тестовым runner. При пустом наборе маршрутов apply сообщил об изменении и вызвал тестовый set. После сценария `true → внешний false → apply true` rollback сообщил `already_restored`, а тестовое состояние осталось true.
- `hub-check` проверяет наличие тега и настройки у локальной машины, но не сравнивает её IP с `100.64.0.10`. Диагностика на другом узле с тем же тегом может ошибочно подтвердить роль ожидаемого коннектора.
- До версии 8.4.0 флаг `--max-filesize` не ограничивает поток неизвестной длины, а проверка Python выполняется после захвата всей выдачи в память. Для жёсткого предела нужен ограниченный приём тела. [Документация curl](https://curl.se/docs/manpage.html#--max-filesize)

## Границы подтверждённого

Применение RouteAll журналируется до изменения, и тесты имитируют сбой после записи настройки. Текущий формат отчёта ограничивает доказательство внешнего IP контрольным endpoint и требует отдельной приёмки Codex. Для запуска пользователем важны проверка всех используемых DNS-ответов, проверка обычного egress отдельно, выбранный транспорт IPv6 и сверка endpoint после входа, запроса и потокового ответа.

## Перепроверка исправлений

При финальной перепроверке прошли 90 тестов и синтаксическая проверка launcher. Исходные замечания выше описывают первую версию кода.

| Участок | Результат повторной проверки |
|---|---|
| Защита хаба | Если Tailscale установлен, а Python отсутствует, launcher останавливается до apt. Если Python есть, но требуется tmux, общая предварительная проверка CLI использует те же `--profile` и `--state-dir`, что и основная команда. Wizard при необходимости создаёт согласованный профиль до сверки адреса и apt. Команды диагностики и настройки профиля могут выполниться без установки tmux. CLI сверяет адрес из профиля перед установкой, регистрацией, изменением маршрутов и запуском Codex. `hub-check` сравнивает локальный IP с адресом из профиля. `100.64.0.10` и `tail000000.ts.net` обозначают примеры для документации. |
| Предварительная проверка RouteAll | До изменения и повторно под блокировкой проверяются маршруты /32 ожидаемого хаба, прочие предложения, доступность IPv6 и переопределения proxy/TLS. Реальная доступность этих данных у нового клиента до включения RouteAll требует проверки. Одобренные маршруты IPv6 отклоняются до применения, даже если ядро ещё считает адрес AAAA недостижимым. Успешный apply по-прежнему изменяет глобальную настройку клиента. Если последующая проверка публичного IP не пройдёт, значение останется включённым до rollback. |
| Восстановление RouteAll | При новой операции baseline обновляется. При незавершённой сохраняется ранее записанный baseline. Тест перехода `true → внешний false → apply true → rollback` проходит. |
| Смена профиля | Завершённая операция переносится в историю, после чего новый профиль получает отдельную привязку. |
| Доверие к загрузке и комплектность Codex | Поиск команды для проверки установщиком использует контролируемый PATH. Обнаруженный неполный канонический пакет блокирует шаг установки с инструкцией по восстановлению. Проверка наличия файлов подтверждает комплектность, а хеши и подписи относятся к полученным артефактам. |
| Запуск Codex с правами root | В проверенной реализации это предусмотренный режим работы на выделенной VM. Проверка сети выполняется перед запуском. Контекст root даёт Codex и запускаемым им командам права root в пределах действующих ограничений. |
| Контрольная HTTPS-проба | curl запускается с `--disable`, а настройки TLS из окружения блокируются по именам переменных. Зафиксированный внешний IP подтверждает запрос пробы к согласованному серверу. Проверка доступа Codex к фактическим endpoint, включая переопределённый провайдер, остаётся отдельной. |
| Объём ответа пробы | Runner прерывает сбор при превышении 2 МиБ на поток и по тайм-ауту. Для curl до 8.4.0 при ответе неизвестной длины рабочий предел памяти задаёт Runner, а фильтр пробы отклоняет тело свыше 64 КиБ после получения. [Документация curl](https://curl.se/docs/manpage.html#--max-filesize) |
| Привилегированные пути | Launcher задаёт PATH и PYTHONPATH, CLI использует домашний каталог root и проверяет владельцев, права и отсутствие ссылок в предках каталога состояния. Явный `--profile` остаётся источником данных, которому должен доверять оператор. Используйте проверенную копию репозитория при запуске от root. |
| Область маршрутов | Встроенная проверка рассчитана на текущий снимок точных /32 и блокирует лишние маршруты. Ввод нового или ротация старого адреса может потребовать нового одобрения и сверки политики. Узел может принять новые маршруты, которые control plane одобрит уже после проверки. Использовать ограниченные утверждённые назначения и права доступа, согласованные администратором tailnet. [Разделение одобрения маршрутов и доступа](https://tailscale.com/docs/reference/route-injection) |

Вывод о пригодности пилота зависит от установки на выделенной VM и реальной проверки после подготовки хаба. Предварительный аудит и HTTPS-проба описывают состояние на момент проверки.
